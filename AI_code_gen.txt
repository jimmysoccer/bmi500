FAILURE-MODE ASSESSMENT
-----------------------

1. Unequal vector lengths
   Risk: an implementation based on zip() could silently ignore extra values.
   Guard: dot_product checks both lengths and raises ValueError.

2. Matrix column count does not match vector length
   Risk: the multiplication is undefined or could produce incomplete results.
   Guard: matvec_multiply compares the first row width with vector length.

3. Ragged matrix
   Risk: different rows would have different dimensions.
   Guard: every row is checked against the width of the first row.

4. Non-iterable or incorrectly shaped inputs
   Risk: a scalar, string, or flat list could fail later with a confusing error.
   Guard: inputs and rows are converted to lists inside clear type checks.

5. Non-numeric elements
   Risk: Python may perform unintended operations, such as string repetition.
   Guard: every vector and matrix value must be a real number.

6. Boolean values
   Risk: bool is a subclass of int, so True and False can silently act as 1 and 0.
   Guard: booleans are rejected explicitly.

7. NaN or infinity
   Risk: non-finite inputs silently contaminate all later calculations.
   Guard: math.isfinite is checked for every numeric value.

8. Caller input mutation
   Risk: changing the caller's matrix or vector creates unexpected side effects.
   Guard: the implementation works on newly materialized lists; tests verify
   that original inputs remain unchanged.
